- Derived key system requirements from user stories
- Selected Agile elements to use: User Stories, Kanban Board, and Agile Development Diary
- Created a GitHub account and repository for the project
- Set up a Kanban board using GitHub Projects
- Defined workflow columns: To Do, In Progress, Done
- Created and structured issues based on project requirements
- Broke down high-level tasks into smaller, manageable development issues
- Defined labels for issue categorisation (frontend, backend, database, auth, admin, testing, documentation, deployment)
- Defined priority labels using MoSCoW (must-have, should-have, could-have)

## Problems / Blockers

- Deciding on the correct level of detail for issues (too large vs too small)
- Understanding how to structure issues and labels effectively in GitHub

## Decisions Made

- Chose to use one issue per task instead of grouping tasks within a single issue
- Chose to use labels for categorisation instead of parent-child issue relationships
- Decided to simplify the Kanban board to three columns (To Do, In Progress, Done)
- Selected FILMHOUSE as the project name
- Decided not to include a separate Testing column and instead use testing as dedicated issues
