## Problems / Blockers

- Needed to determine the best backend structure for returning booking-related movie and screen data without duplicating database fields
- Encountered frontend authentication state inconsistencies after JWT token expiry
- Initial cancellation button styling appeared too visually aggressive compared to the existing FilmHouse colour palette
- Needed to restructure component-level functions after accidentally placing handlers inside useEffect scope

## Decisions Made

- Decided to use reusable BookingCard components instead of hardcoded booking layouts
- Chose to keep database tables normalised rather than duplicating movie and screen fields inside the Booking table
- Decided to return additional booking display data through API response formatting instead of adding redundant database columns
- Chose to use a modal confirmation flow before booking cancellation to prevent accidental destructive actions
- Decided to redirect users to the Login page after expired session detection instead of leaving them on protected pages
- Chose to keep cancellation status updates inline on the My Bookings page instead of requiring a page refresh
