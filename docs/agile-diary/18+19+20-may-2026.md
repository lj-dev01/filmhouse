## Problems / Blockers

- Needed to recreate and reseed the SQLite database after schema changes. Database file could not initially be deleted because it was still in use by the backend server

- Encountered expired/invalid JWT token issues when testing bookings
- Needed to determine the best user flow for booking interactions without excessive page redirections

## Decisions Made

- Decided to use reusable MovieCard components instead of hardcoded movie layouts
- Decided to store poster images in the frontend public folder and reference them using poster_url
- Chose to keep movie/showtime browsing accessible without requiring login
- Decided that booking actions should require authentication
- Chose to use a slide-in booking panel instead of a separate booking page
- Decided to display booking success state within the booking panel rather than redirecting immediately
- Chose to allow users to continue browsing after successful booking instead of forcing navigation away from the Showtimes page
- Decided to display both screen name and screen type together in the UI
- Chose to keep ticket quantity controls as + / − buttons instead of editable input fields for simpler validation and UX consistency
