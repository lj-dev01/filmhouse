- Added shared handling for authentication API errors caused by missing or expired tokens
- Added a shared session expiry message for consistent user feedback

- Updated Admin Dashboard page to handle admin session expiry at dashboard level
- Added admin session checks before switching dashboard tabs
- Added admin session checks before opening protected admin action modals

- Updated Navbar authentication state so links update after login, logout or session clearing
- Updated Login page to save tokens through the shared auth helper
- Updated route guards to use the shared token validation logic

## Problems / Blockers

- Authentication expiry logic was repeated across several frontend pages and admin tab components
- Navbar state became inconsistent with protected page state when tokens were removed or expired
- Admin tabs were handling auth errors separately even though they are all displayed inside the Admin Dashboard


## Decisions Made

- Decided to move shared auth session logic into a reusable frontend auth helper file
- Decided to keep token expiry handling trigger-based instead of using an automatic timer/checker
- Decided that Admin Dashboard should handle admin session expiry for all dashboard tabs
- Decided that admin tab components should not contain repeated session expiry logic
- Decided to clear the saved token when an expired or invalid session is detected so the Navbar updates to logged-out state
- Decided to use a consistent expired session message across relevant protected flows
