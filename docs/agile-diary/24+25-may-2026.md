## Problems / Blockers

- Initial admin bookings response did not include related movie, user and screen fields, causing missing data in the UI
- Showtime creation initially caused the UI to go blank because the POST response did not include the same formatted screen fields as the GET showtimes endpoint
- Needed to refetch showtimes after creating a showtime so the frontend received consistent showtime data
- Needed to decide whether Screens required its own admin tab
- Admin Dashboard component became too large and difficult to maintain before being split into separate tab components
- Needed to handle destructive actions carefully using confirmation prompts

## Decisions Made

- Decided to use one Admin Dashboard page with tabs instead of separate admin pages
- Decided to split each admin tab into its own component for maintainability
- Decided to keep Users tab read-only because user deletion and role management were outside the required scope
- Decided that newly created showtimes should use the selected screen capacity as the default available seats
- Decided to refetch showtimes after creation instead of relying on the POST response shape
- Decided to keep movie delete as a hard delete, while cancelling related bookings and removing related showtimes through backend logic
- Decided to reuse existing confirmation modal, success message and error message styling for consistency
- Decided to keep the homepage minimal with only a hero section
- Decided against adding multiple homepage sections to avoid unnecessary complexity
